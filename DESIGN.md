# State observation page

The page follows `codex-proxy-rs/docs/theme.md` and the official workbench plugin entry pattern. Public `@codex-proxy/ui` is pinned to the v0.2.0 commit. Host-injected `--cp-*` tokens remain the theme authority; the page neither reads cookies nor fetches host endpoints. The IIFE entry and relative stylesheet are compatible with the host resource rewriting pipeline. `dist/` contains `index.html`, `app.js`, and `app.css`, which packaging places under `web/`. The host-owned document title remains `State 观测` and is not rewritten by the app.

## Composition

Use shared BaseButton, BaseInput, BaseCard, BaseTag, BaseEmpty, BaseModal, BaseConfirmModal and BaseTablePagination primitives, their font stack, semantic colors, focus treatment and density. Tailwind's standard 4px spacing scale and the public theme's typography/radius/shadow tokens provide the layout scale. A compact scope toolbar leads into five bounded summary cards and the aggregate account/model table; smaller widths stack filters and cards. Tables scroll within their own region, never the page. Model and account actions are real keyboard-focusable buttons.

Account names are the primary labels, with IDs as secondary text to disambiguate duplicates. Empty names fall back to IDs. Names come from the official non-credential `host.data.accounts.list` (`account_facts`) projection; permissions are eliminated under the host's complete trust model, while the browser bridge continues to project only ID, name, and enabled status (omitting email). The default view uses `POST api/overview` with a 20-account page limit and follows `nextCursor` until the catalog is complete; it includes disabled accounts, empty accounts and per-account read failures. While loading or after cancellation, the toolbar and summary say "已加载 N 个账号" and never claim a global total. `error: unavailable` stays visible as a failure and is never rendered as unobserved or disabled observation.

The overview uses one expanded disclosure per account, with a nested model table. Account names, IDs, model count and account status belong to the parent header; model State lengths and observations belong to the child table. Native disclosure controls provide keyboard expansion/collapse. Local pagination defaults to 10 whole accounts, never splitting child models across pages. Name/ID filtering selects groups; model/status filtering narrows children while retaining their account parent. Empty and unavailable accounts remain explicit groups. Details load lazily via `api/account`; their title uses the name and their subtitle preserves the ID. Detail/settings errors never hide the loaded overview.

Observation details contain fingerprints, length distributions and retained recent history, never raw State. Rule results are not account health. Local expiry is not upstream validity. Counts represent bounded retained observations, not lifetime totals or complete auditing.

## Data and editing

All API replies are parsed as unknown and validated at the bridge boundary; the overview schema rejects history and length fields so production cannot accidentally trust a richer or malformed summary. Cursor requests are JSON POST bodies. The overview loader is sequential, shows page progress, can be cancelled between page requests, retries from the last successful cursor, and uses a run token so stale pages cannot overwrite a newer load.

Refresh retains dirty settings and their original configuration version. A 409 retains the draft and blocks saving until the user explicitly loads the current configuration, preventing silent overwrites. Save errors, success feedback and the conflict recovery action stay in the fixed modal footer rather than below the scrolling form. A null expectedVersion is sent only when the fetched account has no configuration. Closing a dirty detail modal is guarded by an explicit confirmation, including Escape and the close icon; saving prevents closing or switching accounts. A successful save updates the account's overview summaries and status counts immediately and restores keyboard focus to the close control. Request sequence IDs prevent stale detail responses from replacing a newer account.

Production includes no fixture bridge or generated observations. `frontend/preview.html` is an explicit development-only Vite entry with isolated fixtures and public theme initialization, never referenced from `main.ts` or included in `dist/`. Add `?theme=dark`, `?scenario=empty`, `?scenario=partial-error`, `?slow`, or `?conflict` for those preview states. The default preview contains 56 accounts, including empty, disabled, unavailable and mixed model states, to exercise cursor loading and local pagination. Real host integration and package validation remain owned by the parent task.

## Verification

Pinned dependencies install through pnpm, including the allowlisted public UI preparation script. `pnpm typecheck`, `pnpm lint`, `pnpm test`, and `pnpm build` validate the frontend. Boundary tests cover rule parsing, model normalization, bridge pagination query encoding, malformed replies, overview strictness, cursor aggregation, cancellation, retry cursor state, dirty-draft/409 behavior and typed failures. No tests rely on sleeps or prose matching. The local language-server diagnostic tool lacks its executable; vue-tsc supplies compiler diagnostics instead. The parent owns production binary/bridge roundtrip QA and final packaging.
